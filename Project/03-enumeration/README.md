# 웹 애플리케이션 및 API 정보 확인

## 1. 실습 목적
- 대상 웹 애플리케이션의 접근 상태와 응답을 확인
- HTML에서 불러오는 JavaScript 파일과 API로 보이는 경로를 조사
- 추가 분석할 항목을 선정하기 위한 기초 정보 수집

## 2. 대상 환경
- 공격자: Kali Linux (10.10.10.3)
- 대상 서버: Ubuntu Server (10.10.10.4)
- 대상 애플리케이션: OWASP Juice Shop
- 웹 포트: 3000/tcp
- 접속 주소: `http://10.10.10.4:3000`

## 3. 수행한 작업

### 웹 포트 확인
- Nmap으로 대상의 3000번 포트를 확인
- 확인 결과: `3000/tcp open`
- 이 결과는 해당 포트가 열려 있다는 뜻이며, 그 자체로 취약점을 의미하지 않음

### HTTP 응답 확인
- `curl`로 HTTP 응답 헤더와 HTML을 확인
- 응답 코드와 헤더를 확인하고 HTML에서 JavaScript 파일 경로를 살펴봄

### JavaScript 경로 조사
- HTML에서 `polyfills.js`, `scripts.js`, `main.js` 등의 파일 경로를 확인
- `main.js`에서 API로 보이는 경로를 추출
- 이 단계에서는 경로를 확인한 것이며, 모든 API 기능을 검증한 것은 아님

### 상품 검색 API 확인
- 상품 검색 API에 `q=apple` 검색어로 요청
- HTTP 200 응답과 JSON 형식의 상품 데이터를 확인
- 응답에서 상품의 `price` 및 `deluxePrice` 필드를 관찰

## 4. 결과 해석
- 웹 애플리케이션에 접근할 수 있으며, 상품 검색 API가 JSON 데이터를 반환하는 것을 확인
- API 응답에서 확인한 가격 필드는 이후 클라이언트 코드 분석의 단서로 사용
- API 응답이 정상적으로 반환됐다는 사실만으로 보안 취약점 여부를 판단할 수는 없음
